# 마스킹 · 공유 범위 · 재미 코너 취급

---

## 스크립트가 하는 일 / 안 하는 일

**하는 일**
- `~/.claude/` 와 `~/.claude.json` 을 **읽기만** 한다
- 집계 결과를 지정한 경로에 JSON 한 개로 쓴다

**안 하는 일**
- 네트워크 통신 (요청·업로드·전송이 코드에 없다)
- 원본 파일 수정·삭제
- 외부 패키지 설치 (표준 라이브러리만 쓴다)

코드 전문이 [scripts/cc_usage.py](../scripts/cc_usage.py) 에 있으니 직접 확인하면 된다.

## 마스킹 규칙

### 가릴 것 → `***`

- API 키 · 액세스 토큰 · 비밀번호 · 시크릿
- 주민번호 · 전화번호 · 이메일 · 계좌번호
- 고객 개인정보, 고객사 실명
- 사내 비공개 URL · 내부 IP · DB 접속 정보

### 그대로 둘 것

- 프로젝트명 · 저장소명 · 브랜치명 · 파일경로
- 사용한 도구·모델·스킬 이름

**이유**: 파트 내 비교에 식별이 필요하다. 프로젝트명을 가리면 3장(프로젝트별 현황)이 무의미해진다.
대신 **사외 공유는 금지**한다.

## 커밋하지 말 것

| 파일 | 이유 |
|---|---|
| `cc_usage_stats.json` | **프롬프트 원문이 통째로** 들어 있다 (`speech.samples_*`, `top_sessions.first_prompt`). gitignore 되어 있다 |
| `.claude/settings.local.json` | 개인 권한 설정 |
| `.omc/` · `.idea/` | 로컬 툴링/IDE 런타임 상태 |

커밋 대상은 `data/` 의 **3종**이다 — `data/*.md`(보고서) · `data/*.json`(요약) · `data/*.html`(개인 시각화).

**이 저장소는 public 이다. `data/` 에 커밋하는 것은 `.md` 를 포함해 인터넷에 공개된다.**
프로젝트명·저장소명은 그대로 두는 것이 원칙이지만(파트 내 비교에 식별이 필요하다),
**사내 프로젝트명이 외부에 노출되면 곤란한 경우 관리자와 상의**한다.

그중에서도 **`.json` 과 `.html` 은 GitHub Pages 대시보드로도 노출된다. `.md` 보다 노출 범위가 넓다.**
그래서 이 두 파일에는 **프롬프트 원문 · 성별 예상 · 비용(`lastCost`)을 넣지 않는다.**
정본은 [SUMMARY_SCHEMA.md](SUMMARY_SCHEMA.md) 이고, 금지 키가 들어 있으면 `build_site.py` 가 빌드를 거부한다.

**회신 전에 한 번 훑어볼 것.**
5-7절(실제 프롬프트 표본)과 7장(대표 사례)에 지우고 싶은 내용이 있으면 지우고 보내면 된다.

## 8장과 9장을 분리한 이유

| 장 | 근거 | 취급 |
|---|---|---|
| **8장 업무 성향** | 화법 마커, 도구 사용 비율, 서브에이전트 위임률, 재지시 빈도 — **인용 수치가 붙는다** | 실제 보고에 쓸 수 있다 |
| **9장 재미 코너** | 근거 강도 `약함` 이하 | 아이스브레이커로만 쓴다 |

섞이면 추측이 사실처럼 회람된다. **같은 무게로 읽지 마라.**

---

## 9장 근거 강도 표기 (필수)

| 항목 | 근거 강도 | 무엇으로 찍는가 |
|---|---|---|
| MBTI | **약함** | E/I 외부 위임 · S/N 지시 구체성 · T/F 칭찬·사과 마커 · J/P 계획 우선도 |
| 나이대 | **약함** | ㅋㅋ/ㅎㅎ · 이모지 · 말줄임표 · 존댓말 습관 · 야간 작업 비율 |
| 성별 | **거의 없음** | 신호가 빈약함을 명시. **확신 표현 금지** |
| 혈액형 | **없음 (무작위)** | 데이터 신호가 0이라는 걸 밝히고, 억지 논리를 한 줄 붙이는 게 규칙 |
| AI 사용 전문가 지수 | **중간(산식 공개)** | 5축 산식([SUMMARY_SCHEMA.md](SUMMARY_SCHEMA.md)). 재미용이며 평가 지표가 아님을 명시 |

혈액형을 "없음(무작위)" 이라고 대놓고 쓰는 게 규칙인 이유: 확신에 찬 오답이 회람되는 것보다 낫고,
근거가 전혀 없다고 밝히는 쪽이 실제로 더 웃긴다.

## 사람에 대해 쓸 때

- **호의적으로 쓴다.** 재미 코너는 놀리는 자리가 아니다
- 외모 · 성격 결함 · 업무 능력 비하로 읽힐 표현을 쓰지 않는다
- 성별을 확신 표현으로 쓰지 않는다 — 팀 전체에 회람되는 문서다. 틀리면 그 자리가 어색해진다
- 9장은 **본인이 회신 전 통째로 지워도 되는 장**임을 보고서 마지막에 반드시 안내한다
