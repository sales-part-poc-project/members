# members — Claude Code 활용 실태 진단

파트원 각자가 **자기 로컬 사용 이력**을 분석해서, **같은 양식의 보고서**를 뽑는 저장소입니다.

Claude Code 를 열고 **`진단`** 이라고만 치면 끝입니다. 나머지는 전부 자동입니다.

---

## 파트원용 — 3단계

### 1. 저장소를 받아서 그 안에서 Claude Code 를 연다

```bash
git clone <이 저장소 주소> members
cd members
claude
```

### 2. `진단` 이라고 입력한다

이름 3줄만 물어봅니다. 답하고 나면 끝까지 알아서 진행합니다.

```
> 진단
```

집계는 보통 5초, 이력이 많으면 1~2분 걸립니다.

### 3. 생성된 3개 파일을 커밋한다

`data/{파트}_{이름}_{YYYYMMDD}` 이름으로 **`.md` · `.json` · `.html` 3개**가 만들어집니다.

```bash
git add data/영업1파트_홍길동_20260828.md \
        data/영업1파트_홍길동_20260828.json \
        data/영업1파트_홍길동_20260828.html
git commit -m "📝 홍길동 진단 보고서 (2026-08-28)"
git push
```

푸시하면 약 1~2분 뒤 **통합 대시보드**에서 파트 전원의 요약을 한눈에 볼 수 있습니다 —
<https://sales-part-poc-project.github.io/members/>

> **9장(재미 코너)이 부담스러우면 지우고 보내셔도 됩니다.** 나머지 장은 그대로 두세요.

## 무엇이 나오나

| 장 | 내용 |
|---|---|
| 0 | 집계 개요와 한계 — 데이터 구간 3종의 실제 시작~종료일 |
| 1 | 한 줄 요약 |
| 2~3 | 사용 규모 · 프로젝트별 현황 |
| 4 | 워크플로 패턴 — 도구 분포, **OMC 명령어 사용 비중**, 서브에이전트·모델·MCP, **자동화 심도** |
| 5 | **프롬프트 습관과 말투** — 존대/반말 비율, 종결 표현 지문, 어휘 지문, 화법 마커, 대화 리듬, **말투 재현** |
| 6 | 커스터마이징 자산 — CLAUDE.md·에이전트·커맨드·훅. 파트에 공유할 만한 것 지목 |
| 7 | 대표 사용 사례 3~5건 |
| 8 | **업무 성향 프로파일** — 5개 축을 5점 척도 + 인용 수치로 (+ 작업 리듬·관심 영역 서술) |
| 9 | **재미 코너** — MBTI·나이대·혈액형, **AI 사용 전문가 지수** 등 (근거 강도 표기) |
| 10 | 효과 · 한계 · 개선 요청 |
| 11 | 부록 — 원시 수치 |

전체 템플릿은 [docs/REPORT_TEMPLATE.md](docs/REPORT_TEMPLATE.md) 에 있습니다.

### 산출물 3종

같은 이름(stem)으로 `data/` 에 3개가 나옵니다.

| 파일 | 무엇 | 만드는 주체 |
|---|---|---|
| `.md` | 위 0~11장 보고서 — 사람이 읽는 본문 | Claude |
| `.json` | 기계가 읽는 요약. 대시보드는 이것만 읽습니다 ([스키마](docs/SUMMARY_SCHEMA.md)) | Claude |
| `.html` | 내 결과 시각화 페이지. 브라우저로 바로 열어보면 됩니다 | `scripts/build_site.py` 가 `.json` 에서 렌더 |

`.html` 을 스크립트가 만드는 이유는 **사람마다 같은 비주얼이어야 나란히 놓고 비교가 되기** 때문입니다.
직접 고치지 마세요 — 다시 렌더하면 덮어써집니다.

## 말투는 어떻게 뽑나

한글이 포함된 자연어 프롬프트만 모아 분석합니다. 형태소 분석기 없이 **정규식만** 쓰므로 설치할 것이 없습니다.

- **존댓말 / 반말 / 체언종결 비율** — 마지막 문장의 종결 토큰으로 판정
- **종결 표현 지문** — 실제 입버릇. `해줘` `말야` `같아` 처럼 그 사람만의 어미가 드러납니다
- **프롬프트 첫 단어** — 대화를 여는 습관 (`이어서` `일단` `아니` …)
- **어휘 지문** — 조사를 떼어낸 명사 중심 상위 40개
- **화법 마커 10종** — 100건당 출현 수. 불만·교정 / 완곡·탐색 / 검증요구 / 강조·단정 / 칭찬·수용 / 위임·자율 …
- **대화 리듬** — 프롬프트 간격 중앙값, 20자 이하 짧은 후속 지시 비율(재지시 빈도)
- **말투 재현** — 지문을 근거로 **그 사람이 쓸 법한 가상 프롬프트 3개**를 지어냅니다

자세한 필드 해설은 [docs/SPEECH_ANALYSIS.md](docs/SPEECH_ANALYSIS.md).

## 안전한가

- 집계 스크립트([scripts/cc_usage.py](scripts/cc_usage.py))는 **읽기 전용**이고 **네트워크를 쓰지 않습니다.** 코드 전문이 저장소에 있으니 직접 확인하세요.
- 표준 라이브러리만 씁니다 (Python 3.9+). 설치할 패키지가 없습니다.
- 읽는 곳은 `~/.claude/` 와 `~/.claude.json` 뿐입니다.
- API 키·개인정보·고객사 실명은 마스킹하도록 지시되어 있습니다. 다만 **회신 전 한 번 훑어보시길** 권합니다.
- 중간 산출물 `cc_usage_stats.json` 에는 **프롬프트 원문이 통째로** 들어 있습니다. gitignore 되어 있으니 커밋하지 마세요.
- 커밋하는 `.json` · `.html` 은 push 하면 **GitHub Pages 로 공개**됩니다. `.md` 보다 노출 범위가 넓으므로 프롬프트 원문·성별 예상·비용은 이 두 파일에 들어가지 않도록 되어 있습니다 ([스키마](docs/SUMMARY_SCHEMA.md)).
- **이 저장소는 public 입니다.** `data/` 에 커밋하는 내용은 `.md` 를 포함해 **인터넷에 공개**됩니다. 보고서에는 프로젝트명·저장소명을 그대로 두는 것이 원칙이지만, **사내 프로젝트명이 외부에 노출되면 곤란한 경우 관리자와 상의**하세요.

자세한 규칙은 [docs/PRIVACY.md](docs/PRIVACY.md).

## 취합하는 사람용

### 통합 대시보드

파트원이 `data/` 에 3종 파일을 push 하면, GitHub Actions 가 대시보드를 다시 빌드해 GitHub Pages 로 배포합니다 (약 1~2분).

<https://sales-part-poc-project.github.io/members/>

- 대시보드는 `data/**/*.json` 만 읽습니다 (`.md` 는 파싱하지 않습니다)
- 같은 사람이 여러 번 뽑았으면 **(파트, 이름) 별 최신 날짜 1건**을 대표로 쓰고 나머지는 이력으로 표시합니다
- 잘못된 JSON 은 **그 파일만 건너뛰고** 이유를 로그에 남깁니다. 한 사람 때문에 전체 배포가 막히지 않습니다

**로컬 미리보기** (push 없이 확인)

```bash
python3 scripts/build_site.py --out _site && open _site/index.html
```

**최초 1회 설정** — 저장소 관리자가 GitHub 웹에서 한 번 해야 합니다.

- 저장소 **Settings → Pages → Build and deployment → Source** 를 **`GitHub Actions`** 로 지정
  (워크플로가 자동으로 켜보지만 권한에 따라 수동 지정이 필요합니다)
- 이 저장소는 **public 이라 Pages 가 무료로 동작**합니다 (참고: private 으로 바꾸면 Pages 에 Pro / Team / Enterprise 플랜이 필요해집니다)
- 배포가 안 되면 **Actions 탭**에서 실패한 워크플로 로그를 확인하세요

### 읽는 순서

1. **2~4장**을 나란히 놓고 규모와 작업 방식을 비교합니다
2. **6장**에서 각자 만든 자산 중 **파트에 공유할 만한 것**을 모읍니다 — 이게 실질적인 소득입니다
3. **10장**의 "잘 안 되는 유형"과 "제안"을 모아 교육·표준화 주제를 뽑습니다
4. **5장·8~9장**은 아이스브레이커로 씁니다

### 비교할 때 주의

- **비용으로 줄세우지 마세요.** `lastCost` 는 프로젝트별 마지막 세션 값이라 누적 비용이 아닙니다. 스크립트도 이 값을 총액으로 쓰지 않습니다.
- **트랜스크립트는 약 30일 후 자동 삭제됩니다.** 오래 안 쓴 사람일수록 최근 30일 수치가 비어 보입니다. 장기 지표(세션 수·프롬프트 이력)와 함께 읽으세요.
- **8장과 9장을 같은 무게로 읽지 마세요.** 8장은 인용 수치가 붙지만 9장은 근거 강도가 `약함` 이하입니다. 9장이 빠진 회신이 와도 정상입니다.

### 스크립트를 고쳐야 한다면

`scripts/cc_usage.py` 는 **모두가 같은 로직으로 집계해야** 비교가 성립합니다.
`scripts/build_site.py` 도 같습니다 — 사람마다 다른 렌더러를 쓰면 대시보드가 서로 다른 것을 보여줍니다.

개인이 로컬에서 고치지 말고, 저장소에 반영해서 **전원이 다시 돌리는** 방식으로 바꾸세요.

## 저장소 구조

```
members/
├── CLAUDE.md                  # "진단" 트리거 + 절차 정본 (Claude 가 읽는 파일)
├── README.md                  # 이 문서
├── .gitignore                 # cc_usage_stats.json · _site/ 제외
├── scripts/
│   ├── cc_usage.py            # 집계 스크립트 (읽기 전용, 표준 라이브러리만)
│   ├── build_site.py          # .html 렌더 + 통합 대시보드 빌드
│   ├── test_build_site.py     # build_site.py 테스트 (CI 에서 실행)
│   └── fixtures/              # 테스트·데모용 가짜 요약 JSON
├── docs/
│   ├── DATA_SOURCES.md        # 데이터 원본 · 집계 구간 3종 · 수치 함정
│   ├── REPORT_TEMPLATE.md     # 0~11장 보고서 템플릿 정본
│   ├── SUMMARY_SCHEMA.md      # 요약 JSON 스키마 정본 · 금지 키
│   ├── SPEECH_ANALYSIS.md     # speech 블록 필드 해설
│   └── PRIVACY.md             # 마스킹 규칙 · 공유 범위 · 재미 코너 취급
├── data/                      # 진단 산출물(.md/.json/.html)이 모이는 곳
│   └── README.md              # 회신 방법 · 보내기 전 점검
├── .github/workflows/
│   └── pages.yml              # push → 대시보드 빌드 → GitHub Pages 배포
└── .claude/commands/진단.md    # /진단 슬래시 커맨드
```
