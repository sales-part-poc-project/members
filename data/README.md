# data

진단 산출물이 모이는 곳. 여기에 커밋된 것이 GitHub Pages 통합 대시보드의 재료가 된다.

## 파일명 규칙

한 사람의 한 번 진단은 **stem 이 같은 3개 파일**로 남는다.

```
data/{파트}_{이름}_{YYYYMMDD}.md     ← 보고서 (사람이 읽음)
data/{파트}_{이름}_{YYYYMMDD}.json   ← 요약 (대시보드가 읽음)
data/{파트}_{이름}_{YYYYMMDD}.html   ← 개인 시각화 (브라우저로 열어봄)
```

예: `data/영업1파트_홍길동_20260828.md`

- 파트·이름에 **공백을 넣지 않는다** (공백은 하이픈 `-` 으로)
- 언더스코어 `_` 는 구분자이므로 파트·이름 안에 쓰지 않는다
- 세 파일의 **stem 이 완전히 같아야** 한다
- 같은 사람이 다시 뽑으면 **날짜가 다른 새 파일**로 남긴다. 덮어쓰지 않는다 — 시간에 따른 변화를 보기 위해서다.
  대시보드는 (파트, 이름) 별 **최신 날짜 1건**을 대표로 쓰고 나머지는 이력으로 표시한다

## 누가 무엇을 만드나

| 파일 | 만드는 주체 |
|---|---|
| `.md` | Claude 가 [../docs/REPORT_TEMPLATE.md](../docs/REPORT_TEMPLATE.md) 대로 작성 |
| `.json` | Claude 가 [../docs/SUMMARY_SCHEMA.md](../docs/SUMMARY_SCHEMA.md) 대로 작성 (`.md` 와 같은 수치) |
| `.html` | **`scripts/build_site.py` 가 `.json` 에서 렌더** — 손으로 쓰거나 고치지 않는다 |

`.html` 을 스크립트가 만드는 이유: 사람마다 비주얼이 다르면 나란히 놓고 비교할 수가 없다.

## 회신 방법

3개 파일을 함께 커밋한다.

```bash
git add data/영업1파트_홍길동_20260828.md \
        data/영업1파트_홍길동_20260828.json \
        data/영업1파트_홍길동_20260828.html
git commit -m "📝 홍길동 진단 보고서 (2026-08-28)"
git push
```

푸시하면 **약 1~2분 뒤** 통합 대시보드에 반영된다: <https://sales-part-poc-project.github.io/members/>

## 보내기 전에

- **이 저장소는 public 이다.** 여기 커밋하는 것은 `.md` 를 포함해 **인터넷에 공개**된다. 프로젝트명·저장소명은 그대로 두는 것이 원칙이지만, **사내 프로젝트명이 외부에 노출되면 곤란한 경우 관리자와 상의**할 것
- **한 번 훑어볼 것.** 5-7절(실제 프롬프트 표본)과 7장(대표 사례)에 지우고 싶은 내용이 있으면 지우고 보내면 된다
- **9장(재미 코너)이 부담스러우면 통째로 지워도 된다.** 나머지 장은 그대로 둔다 (`.json` 은 `fun` 을 `null` 로)
- **`.json` 에 프롬프트 원문·성별 예상이 없는지 확인.** `.json` 과 `.html` 은 GitHub Pages 로 공개되므로 `.md` 보다 노출 범위가 넓다
- API 키·개인정보·고객사 실명이 남아 있지 않은지 확인 (마스킹하도록 지시되어 있지만 최종 확인은 본인 몫)
- `cc_usage_stats.json` 은 커밋하지 않는다 (프롬프트 원문이 통째로 들어 있다 — gitignore 되어 있음)

## 읽는 사람에게

- **8장(업무 성향)과 9장(재미 코너)을 같은 무게로 읽지 말 것.** 8장은 인용 수치가 붙지만 9장은 근거 강도가 `약함` 이하다
- **비용으로 줄세우지 말 것.** 자세한 이유는 [../docs/DATA_SOURCES.md](../docs/DATA_SOURCES.md) 의 "수치 함정" 참고
- 트랜스크립트는 약 30일 후 자동 삭제되므로, 오래 안 쓴 사람일수록 최근 30일 수치가 비어 보인다. 장기 지표와 함께 읽을 것
